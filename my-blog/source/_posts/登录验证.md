# 登录校验

登录校验指的是在服务端接收到浏览器发送的请求时，对请求的用户身份进行校验，以确定该用户是否有权限访问该资源。

## HTTP 协议的无状态性

> **前提：HTTP 协议是无状态协议**

所谓无状态，指的是每一次请求都是独立的，下一次请求并不会携带上一次请求的数据。

浏览器与服务器之间基于 HTTP 协议交互，这就意味着：通过浏览器访问登录接口完成登录操作后，再执行其他业务操作时，服务器并不知道该用户是否已经登录。因为 HTTP 协议的无状态特性，两次请求之间是独立的，无法判断用户是否已登录。

# 会话技术

会话指的是服务器与浏览器之间的一次连接。在一次会话中可以包含多次请求和响应。

## 会话跟踪

会话跟踪是一种维护浏览器状态的方法，服务器需要识别多次请求是否来自同一浏览器，以便在同一次会话的多次请求间共享数据。

### 会话跟踪技术对比

| 技术     | 类型           | 存储位置          | 说明                     |
| :------- | :------------- | :---------------- | :----------------------- |
| Cookie   | 客户端会话跟踪 | 浏览器端          | 数据存储在客户端浏览器中 |
| Session  | 服务端会话跟踪 | 服务器端          | 数据存储在服务端         |
| 令牌技术 | 无状态认证     | 客户端/服务端均可 | 基于 Token 的身份验证    |

---

## Cookie

Cookie 是客户端会话跟踪技术，数据存储在客户端浏览器中。

### 工作原理

1. 浏览器第一次发起请求时，服务器端设置 Cookie
2. 服务器响应数据时，通过**响应头 `Set-Cookie`** 将 Cookie 响应给浏览器
3. 浏览器接收后自动将 Cookie 存储在本地
4. 后续每一次请求都会自动携带 Cookie 到服务端  (通过**请求头 `Cookie`**)
5. 服务端获取 Cookie 的值来判断用户是否已登录

> Cookie 的自动化处理是因为它是 HTTP 协议支持的标准技术，各大浏览器厂商都实现了这一标准。

### 代码示例

```java
@Slf4j
@RestController
public class CookieController {

    // 设置 Cookie
    @GetMapping("/c1")
    public Result cookie1(HttpServletResponse response) {
        response.addCookie(new Cookie("login_username", "planck"));
        return Result.success();
    }

    // 获取 Cookie
    @GetMapping("/c2")
    public Result cookie2(HttpServletRequest request) {
        Cookie[] cookies = request.getCookies();
        if (cookies != null) {
            for (Cookie cookie : cookies) {
                if (cookie.getName().equals("login_username")) {
                    System.out.println("login_username: " + cookie.getValue());
                }
            }
        }
        return Result.success();
    }
}
```

### 执行流程

- **A.** 访问 `/c1` 接口 → 设置 Cookie → 通过**响应头 `Set-Cookie`** 响应给浏览器 → 浏览器存储 Cookie
- **B.** 访问 `/c2` 接口 → 浏览器自动通过**请求头 `Cookie`** 携带 Cookie 到服务端

### 跨域判断

跨域的判断依据以下三个维度（任一维度不同即为跨域）：

| 维度    | 说明                                    |
| :------ | :-------------------------------------- |
| 协议    | http 与 https 不同                      |
| 域名/IP | 192.168.150.200 与 192.168.150.100 不同 |
| 端口    | 80 与 8080 不同                         |

**示例：**

```
http://192.168.150.200/login.html → https://192.168.150.200/login     协议不同，跨域
http://192.168.150.200/login.html → http://192.168.150.100/login      IP不同，跨域
http://192.168.150.200/login.html → http://192.168.150.200:8080/login  端口不同，跨域
http://192.168.150.200/login.html → http://192.168.150.200/login       不跨域
```

## Session

Session 是服务端会话跟踪技术，数据存储在服务端。Session 的底层其实就是基于 Cookie 来实现的。

### 工作流程

1. 浏览器第一次请求服务器时，获取会话对象 Session
2. 如果是首次请求，Session 不存在，服务器自动创建 Session 对象
3. 每个 Session 对象都有唯一 ID（Session ID）
4. 服务器响应时，将 Session ID 通过 **Set-Cookie** 响应头返回给浏览器
5. Cookie 名称为固定的 `JSESSIONID`，值为 Session ID
6. 浏览器自动将 Cookie 存储在本地
7. 后续每次请求自动携带该 Cookie 到服务端
8. 服务器根据 JSESSIONID 找到对应的 Session 对象

### 代码示例

```java
@Slf4j
@RestController
public class SessionController {

    @GetMapping("/s1")
    public Result session1(HttpSession session) {
        log.info("HttpSession-s1: {}", session.hashCode());
        session.setAttribute("loginUser", "tom"); // 往 session 中存储数据
        return Result.success();
    }

    @GetMapping("/s2")
    public Result session2(HttpServletRequest request) {
        HttpSession session = request.getSession();
        log.info("HttpSession-s2: {}", session.hashCode());

        Object loginUser = session.getAttribute("loginUser"); // 从 session 中获取数据
        log.info("loginUser: {}", loginUser);
        return Result.success(loginUser);
    }
}
```

## 令牌技术

两种传统的会话技术在现代企业开发中存在诸多问题。为了解决这些问题，现代企业开发基本都采用令牌技术来进行会话跟踪。

### 工作原理

1. 浏览器请求登录接口，登录成功后服务端生成**令牌（Token）**
2. 令牌是用户的合法身份凭证，服务端将其响应给前端
3. 前端接收令牌后进行存储（可存储在 Cookie 或 localStorage 中）
4. 后续每次请求都需要携带令牌到服务端
5. 服务端校验令牌有效性：
   - 令牌有效 → 用户已登录
   - 令牌无效 → 用户未登录
6. 如需在多次请求间共享数据，可将数据存储在令牌中

在 JWT 登录认证场景中，整个流程涉及两步核心操作：

1. **登录成功后生成令牌**
2. **每次请求时校验令牌有效性**

# JWT 令牌

JWT 全称 **JSON Web Token**，定义了一种简洁的、自包含的格式，用于在通信双方以 JSON 数据格式安全地传输信息。由于数字签名的存在，这些信息是可靠的。

### 特性

| 特性       | 说明                                                     |
| :--------- | :------------------------------------------------------- |
| **简洁**   | JWT 就是一个简单的字符串，可在请求参数或请求头中直接传递 |
| **自包含** | 可根据需求在 JWT 中存储自定义数据（如用户信息）          |
| **安全**   | 通过数字签名防止篡改                                     |

简单来讲，JWT 就是将原始的 JSON 数据进行了安全的封装，可直接基于 JWT 在通信双方之间安全地进行信息传输。

### JWT 组成结构

JWT 令牌由三部分组成，各部分之间使用英文点（`.`）分割：

```
Header.Payload.Signature
```

<table>
<thead>
<tr>
<th>部分</th>
<th>名称</th>
<th>说明</th>
<th>示例</th>
</tr>
</thead>
<tbody>
<tr><td>第一部分</td><td>Header（头）</td><td>记录令牌类型、签名算法等</td><td>{"alg":"HS256","type":"JWT"}</td></tr>
<tr><td>第二部分</td><td>Payload（有效载荷）</td><td>携带自定义信息、默认信息等</td><td>{"id":"1","username":"Tom"}</td></tr>
<tr><td>第三部分</td><td>Signature（签名）</td><td>防止 Token 被篡改，确保安全性。将 Header、Payload 加入指定密钥，通过指定签名算法计算而来</td><td>-</td></tr>
</tbody>
</table>

> **签名的目的：** 防止 JWT 令牌被篡改。正是因为数字签名的存在，整个 JWT 令牌非常安全可靠。一旦 JWT 中任何一个字符被篡改，校验时都会失败。

### Base64 编码

- 生成 JWT 时会对 JSON 格式的数据进行 Base64 编码
- **Base64** 是一种基于 64 个可打印字符来表示二进制数据的编码方式
- 使用的 64 个字符：`A-Z`、`a-z`、`0-9`、`+`、`/`，以及补位符号 `=`
- 任何数据经过 Base64 编码后，最终都通过这 64 个字符来表示

> **重要：Base64 是编码方式，不是加密方式！**

### 生成 JWT 令牌

```java
@Test
public void testGenJwt() {
    Map<String, Object> claims = new HashMap<>();
    claims.put("id", 10);
    claims.put("username", "itheima");

    String jwt = Jwts.builder()
        .signWith(SignatureAlgorithm.HS256, "aXRjYXN0")
        .addClaims(claims)
        .setExpiration(new Date(System.currentTimeMillis() + 12 * 3600 * 1000))
        .compact();

    System.out.println(jwt);
}
```

### 校验 JWT 令牌

```java
@Test
public void testParseJwt() {
    Claims claims = Jwts.parser()
        .setSigningKey("aXRjYXN0")
        .parseClaimsJws("eyJhbGciOiJIUzI1NiJ9.eyJpZCI6MTAsInVzZXJuYW1lIjoiaXRoZWltYSIsImV4cCI6MTcwMTkwOTAxNX0.N-MD6DmoeIIY5lB5z73UFLN9u7veppx1K5_N_jS9Yko")
        .getBody();
    System.out.println(claims);
}
```

# 统一拦截技术

通过浏览器的开发者工具可以看到，后续请求会在请求头中携带 JWT 令牌到服务端，而服务端需要统一拦截所有请求，判断是否携带合法的 JWT 令牌。

统一拦截所有请求校验令牌的有效性有两种解决方案：

1. **Filter 过滤器**
2. **Interceptor 拦截器**

---

## Filter 过滤器

### 简介

- Filter 表示过滤器，是 JavaWeb 三大组件（Servlet、Filter、Listener）之一
- 过滤器可以把对资源的请求拦截下来，从而实现一些特殊的功能
- 使用过滤器后，访问 Web 服务器上的资源必须先经过过滤器，处理完毕后才可访问对应资源
- 过滤器一般用于完成通用操作：**登录校验、统一编码处理、敏感字符处理**等

### 基本使用

#### 第 1 步：定义过滤器

定义一个类，实现 `Filter` 接口，并重写其所有方法：

```java
public class DemoFilter implements Filter {

    // 初始化方法，Web 服务器启动创建 Filter 实例时调用，只调用一次
    @Override
    public void init(FilterConfig filterConfig) throws ServletException {
        System.out.println("init ...");
    }

    // 拦截到请求时调用该方法，可调用多次
    @Override
    public void doFilter(ServletRequest servletRequest, ServletResponse servletResponse, FilterChain chain)
            throws IOException, ServletException {
        System.out.println("拦截到了请求...");
        // 放行操作
        chain.doFilter(servletRequest, servletResponse);
    }

    // 销毁方法，Web 服务器关闭时调用，只调用一次
    @Override
    public void destroy() {
        System.out.println("destroy ...");
    }
}
```

#### 第 2 步：配置过滤器

- Filter 类上加 `@WebFilter` 注解，配置拦截路径
- 引导类上加 `@ServletComponentScan` 开启 Servlet 组件支持

```java
@WebFilter(urlPatterns = "/*") // /* 表示拦截所有请求
public class DemoFilter implements Filter {
    // ... 同上
}
```

```java
@ServletComponentScan
@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```

> **注意事项：** 在过滤器中如果不执行放行操作 `chain.doFilter(request, response)`，将无法访问后面的资源。

### 登录校验实现

```java
/**
 * 令牌校验过滤器
 */
@Slf4j
@WebFilter(urlPatterns = "/*")
public class TokenFilter implements Filter {

    @Override
    public void doFilter(ServletRequest req, ServletResponse resp, FilterChain chain)
            throws IOException, ServletException {
        HttpServletRequest request = (HttpServletRequest) req;
        HttpServletResponse response = (HttpServletResponse) resp;

        // 1. 获取请求 URL
        String url = request.getRequestURL().toString();

        // 2. 判断是否为登录请求，如果是则放行
        if (url.contains("login")) {
            log.info("登录请求，直接放行");
            chain.doFilter(request, response);
            return;
        }

        // 3. 获取请求头中的令牌
        String jwt = request.getHeader("token");

        // 4. 判断令牌是否存在
        if (!StringUtils.hasLength(jwt)) {
            log.info("获取到 jwt 令牌为空，返回错误结果");
            response.setStatus(HttpStatus.SC_UNAUTHORIZED);
            return;
        }

        // 5. 解析令牌
        try {
            JwtUtils.parseJWT(jwt);
        } catch (Exception e) {
            e.printStackTrace();
            log.info("解析令牌失败，返回错误结果");
            response.setStatus(HttpStatus.SC_UNAUTHORIZED);
            return;
        }

        // 6. 放行
        log.info("令牌合法，放行");
        chain.doFilter(request, response);
    }
}
```

## Interceptor 拦截器

### 简介

- 是一种动态拦截方法调用的机制，类似于过滤器
- 拦截器是 Spring 框架提供的，用来动态拦截控制器方法的执行
- 拦截器的作用：**拦截请求，在指定方法调用前后根据业务需要执行预先设定的代码**

### 基本使用

#### 第 1 步：定义拦截器

实现 `HandlerInterceptor` 接口，并重写其方法：

```java
@Component
public class DemoInterceptor implements HandlerInterceptor {

    // 目标资源方法执行前执行。返回 true：放行；返回 false：不放行
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler)
            throws Exception {
        System.out.println("preHandle ...");
        return true; // true 表示放行
    }

    // 目标资源方法执行后执行
    @Override
    public void postHandle(HttpServletRequest request, HttpServletResponse response,
                            Object handler, ModelAndView modelAndView) throws Exception {
        System.out.println("postHandle ...");
    }

    // 视图渲染完毕后执行，最后执行
    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                 Object handler, Exception ex) throws Exception {
        System.out.println("afterCompletion ...");
    }
}
```

#### 第 2 步：注册配置拦截器

创建配置类，实现 `WebMvcConfigurer` 接口，重写 `addInterceptors` 方法：

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Autowired
    private DemoInterceptor demoInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(demoInterceptor)
                .addPathPatterns("/**"); // /** 表示拦截所有请求
    }
}
```

### 拦截器方法说明

| 方法              | 执行时机                 | 返回值说明                  |
| :---------------- | :----------------------- | :-------------------------- |
| `preHandle`       | 目标资源方法执行前       | `true` 放行，`false` 不放行 |
| `postHandle`      | 目标资源方法执行后       | -                           |
| `afterCompletion` | 视图渲染完毕后，最后执行 | -                           |

### 登录校验实现

#### 定义拦截器

```java
@Slf4j
@Component
public class TokenInterceptor implements HandlerInterceptor {

    @Override

            throws Exception {
        // 1. 获取请求 URL
        String url = request.getRequestURL().toString();

        // 2. 判断是否为登录请求
        if (url.contains("login")) {
            log.info("登录请求，直接放行");
            return true;
        }

        // 3. 获取请求头中的令牌
        String jwt = request.getHeader("token");

        // 4. 判断令牌是否存在
        if (!StringUtils.hasLength(jwt)) {
            log.info("获取到 jwt 令牌为空，返回错误结果");
            response.setStatus(HttpStatus.SC_UNAUTHORIZED);
            return false;
        }

        // 5. 解析令牌
        try {
            JwtUtils.parseJWT(jwt);
        } catch (Exception e) {
            e.printStackTrace();
            log.info("解析令牌失败，返回错误结果");
            response.setStatus(HttpStatus.SC_UNAUTHORIZED);
            return false;
        }

        // 6. 放行
        log.info("令牌合法，放行");
        return true;
    }
}
```

#### 配置拦截器

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Autowired
    private TokenInterceptor tokenInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(tokenInterceptor)
                .addPathPatterns("/**");
    }
}
```

## Filter 与 Interceptor 执行流程

1. 浏览器访问部署在 Web 服务器上的 Web 应用时，**过滤器**先拦截到请求
2. 过滤器执行放行前的逻辑，然后执行放行操作
3. 由于基于 Spring Boot 开发，放行后进入 Spring 环境，准备访问 Controller 接口
4. Tomcat 不识别 Controller 程序，但识别 Servlet 程序。Spring Web 环境提供了核心 Servlet：**DispatcherServlet（前端控制器）**，所有请求先到达 DispatcherServlet，再转发给 Controller
5. 定义了拦截器后，在执行 Controller 方法之前，请求被**拦截器**拦截，执行 `preHandle()` 方法
6. `preHandle()` 返回 `true` 则放行，继续访问 Controller 方法；返回 `false` 则不放行
7. Controller 方法执行完毕后，依次执行 `postHandle()` 和 `afterCompletion()` 方法
8. 返回给 DispatcherServlet，最终执行过滤器中放行后的逻辑
9. 最终给浏览器响应数据
